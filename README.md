# Dynamic Auto — first working version

Buildless, responsive HTML/CSS/JavaScript frontend for GitHub Pages, with a separate Python API, SQLite database, and durable photo uploads. No fake owner login or browser-local inventory. Instagram: https://www.instagram.com/dynamicauto1/

## Included

- Home, searchable/sortable inventory, vehicle detail gallery and specifications, contact, about, privacy, and owner dashboard pages.
- Owner username/password authentication, 8-hour revocable bearer sessions, PBKDF2 password hashing, login and inquiry rate limiting.
- Photo uploads (JPG/PNG/WebP), draft/available/pending/sold listings, editable templates, duplicate-as-draft, deletion and business information settings.
- Buyer inquiries saved to the owner dashboard with new/contacted/closed status. No email or SMS notifications are configured; owner must check the dashboard.
- Explicit sample showroom at `inventory.html?demo=1`. Sample cars are never actual inventory and cannot be inquired about as listed cars. Real inventory starts empty.

## Run it locally

Requires Python 3.12 or later. No packages to install.

1. Run `python backend/set_password.py`. Enter a unique password with 12+ characters. It prints a salt and hash, not your password.
2. Set `OWNER_USERNAME`, `OWNER_PASSWORD_SALT`, and `OWNER_PASSWORD_HASH` privately in your terminal environment using the generated values. Do not commit credentials or put them into config.js.
3. Run `python backend/server.py`.
4. Open `http://localhost:8000` and then `http://localhost:8000/admin.html`.
5. Sign in, add real vehicle photos/details, choose Available, and save. Other browser windows see the same persisted inventory.

The server serves only allowlisted public files, API routes, and uploaded raster images. Database, Python source, and credentials cannot be downloaded through it.

## GitHub Pages + separate backend

GitHub Pages cannot execute Python, protect owner credentials, save shared inventory, or accept uploads. Both deployments are required.

1. Create an empty GitHub repository named `Dynamic-Auto`, branch `main`. Upload this folder's CONTENTS, preserving `.github/workflows/pages.yml`.
2. In repository Settings → Pages, choose GitHub Actions. Included workflow publishes only public frontend files, excluding backend, database and runtime data.
3. Deploy backend from the same repository on a Python host with HTTPS and a persistent disk. `render.yaml` is an optional Render blueprint with persistent disk; it specifies a paid service. Do not assume a free ephemeral disk preserves cars/photos. Another persistent Python host can run `python backend/server.py` behind its HTTPS reverse proxy.
4. Set private host environment variables:
   - `OWNER_USERNAME`: your desired owner username.
   - `OWNER_PASSWORD_SALT` and `OWNER_PASSWORD_HASH`: generated by the password helper.
   - `ALLOWED_ORIGINS`: exact comma-separated FRONTEND ORIGINS, e.g. `https://zayaiken21.github.io` (no repository path) and your backend's HTTPS origin if you use its frontend.
   - `DATA_DIR`: persistent disk directory, e.g. `/var/data`.
   - `PORT`: supplied by host, defaults to 8000.
5. Edit frontend `config.js` and set `apiBase` to your backend HTTPS origin, e.g. `https://YOUR-BACKEND.example` (no `/api`, no trailing slash). Never put a password or secret here.
6. Commit config.js; wait for Pages workflow. Open the real Pages URL shown by GitHub.
7. Open `admin.html`, sign in, fill Business details (phone/email/address/hours), upload real photos, complete a car template, choose Available and save.
8. In a different browser, verify the car appears, submit an inquiry, and confirm it arrives in Owner Studio. Sign out and confirm dashboard API access is denied.

## Operating notes

- No default or hardcoded password. Changing OWNER_PASSWORD_HASH does not immediately revoke existing sessions; clear the sessions table or wait up to 8 hours. Never share the password in a public repository.
- Session tokens live only in the current browser tab's sessionStorage. Sign out invalidates the server session. Use HTTPS in production. CORS allows only the configured frontend origins.
- Single persistent backend instance is assumed for SQLite and rate limits. Do not use multiple isolated replicas. Back up the entire DATA_DIR (database + uploads) regularly with your host's backup tools. Stored inquiries contain personal information; only the owner should have host/database access.
- Uploads are checked by raster signature, filename randomized and served with image content type and nosniff. HEIC, SVG and executable files are rejected. Upload limit: 12 MB per photo, 24 per listing. Strip photo location metadata before uploading if needed. Unused images remain on disk; deleting a listing does not delete photos because duplicated listings may share them. Monitor disk usage.
- Buyer inquiry abuse is rate limited. No financing applications or card payments are collected. This is a contact-based sales site, not checkout.
- Fonts use Google Fonts and illustrative lifestyle/sample photographs use Unsplash. Photos are illustrative and are not claimed as dealer-owned vehicles. Replace hero/about photography with owner-authorized photos when available. Live listings only use owner-uploaded photos.
- Search crawlers can index the HTML home/about/contact pages. Vehicle details are currently loaded through JavaScript at one URL template; server-rendered per-vehicle pages, canonical URLs and a generated sitemap should be added once the final public domain is known. No guaranteed ranking/indexing claims.
- Business address, phone, owner credentials and vehicle stock were not supplied and have not been invented. Instagram account ownership/content was not independently verified.

## Tests

Run `python -m unittest discover -s tests -v`. Integration tests exercise owner access, upload, draft hiding, publication, inquiries, updates, deletion, logout, and private-file protection using isolated temporary storage.
